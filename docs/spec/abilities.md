# MERIDIAN FRACTURE: Abilities, Stealth, Vision, Timed Effects, Zones and Transports (domain spec v2)

> Author role: domain architect for abilities. Binding parents: `docs/ARCHITECTURE.md` (wins on conflict) and the bible in `Input/meridian_agent_reference/`.
> Appendix: `docs/spec/abilities_catalog.md` maps every unit (156), structure (29), research (40), support power (48) and superweapon (8) to primitives, to the data registry kind (`data_balance.md` 7.4), to economy's power kind (`economy.md` 5.18) and to the recommended runtime owner. It is generated by a script that asserts those counts.
> **v2 status.** Written after reading the concurrently published `combat.md`, `data_balance.md`, `economy.md`, `ai.md`, `net.md`. Where they already define a mechanism completely and the seam is clean, this spec *adopts* it (section 1.4 lists every case; section 12 is the reconciliation matrix). Notation: `ASSUMPTION(domain)` = a dependency on another domain; a trailing `*` on a number = prose silent, proposed default. Times are ticks (20 per second) unless written in seconds; distances are sub-cell units (1024 per cell) unless written in cells.

### 1.3 Key state decisions (binding for this domain)

1. **No height occlusion.** Vision is a cell-granular disc; terrain height, buildings and forests never block sight (bit-exact cheap incremental updates, C&C: RA2 behavior).
2. **Membership per data.** `DefEffect.membership` and `DefZone` decide: `latched` (snapshot at activation, the effect follows the unit) for every unit-buff power, `continuous` only for zones that are places (smoke, cover, repair, debris, interception).
3. **One additive temporary layer.** Research (`DefLayer3`) and temporary effects are the same bible layer and **add**; entries sharing a `stack_group` (or `src_key`) count once, the largest absolute delta wins (`data_balance.md` 5.8.2).
4. **Event-driven conditions.** No condition is recomputed per tick per entity: coverage-grid transitions, timers, and a small pull pass over the *watched* entities only.
5. **Combat numbers travel as leases.** Everything that changes damage dealt or taken, range, reload, suppression or EMP behavior reaches combat through its lease API, never through a parallel cache.
6. **Sim state is ints in fixed arrays**; nothing keyed by object reference; vision is computed per group (team when shared vision is on, otherwise per player).

## 3. Public API

All signatures are GDScript 4.7, statically typed. `SimWorld` (sim-core) exposes at least `tick: int`, `rng: SimRng`, `data: GameData`, `map: MapData`, `players`, `spatial: SpatialHash`, `get_entity(eid: int) -> SimEntity` (null if gone; ids are never reused), `rel(a: int, b: int) -> int`, `team_of(pid: int) -> int`, `emit(...)`, and one field per system: `abilities: SimAbilitySystem`, `zones: SimZoneSystem`, `vision: SimVisionSystem`, `combat`, `power`, `economy`, `strategic`, `orders`, `movement`. Per-player research state is `world.players[pid].layer3: DefLayer3` (data). ASSUMPTION(sim-core), section 13.

### 3.1 Tick order and ownership

| Pipeline step | Caller | What this domain does |
|---|---|---|
| 1 CommandSystem | sim-core | `SimAbilityCmds.execute(world, cmd)` for command codes 100 to 105 (section 6) |
| 2 ProductionSystem | production | `abilities.on_spawn(e)` after every spawn; `abilities.on_roster_init(pid)` once at match start; `abilities.on_research_complete(pid, r_idx)` after `DefLayer3.apply_research` |
| 4 PowerSystem | economy / power | `SimPowerFx.validate / apply`; `zones.spawn_warning(...)`; the framework polls `combat.is_functional(launcher)` during a warning |
| 5 OrderSystem | orders | `SimChannel.begin / cancel`, `SimTransport.board / garrison_enter`, `SimMode.request`, `abilities.request_pack` |
| 6 MovementSystem | movement | reads `abilities.speed_units(e)`, `is_immobile(e)`, `is_turn_locked(e)`; writes `cc.ext_moving` |
| **7 AbilitySystem.update** | sim-core | order in 5.6.1: power flips, timers, watch pass, mode protocol (`want_*` in, `ext_*` out), active state machines, auras and heal cadence, auto-cast |
| 8 CombatSystem | combat | reads leases and `ext_*`; calls `zones.intercept_ordinary / intercept_packet`; calls `SimTransport.eject_all` when a container dies; queries `SimVision.can_see / is_known / decoy_identified` |
| **9 ZoneSystem.update** | sim-core | zone lifecycle, membership, effect leases, expiry |
| **10 VisionSystem.update** | sim-core | every `stride`-th tick: grids, masks, ghosts, events |
| 11 CleanupSystem | sim-core | `abilities.on_remove(e, cause)` for every removed entity, ascending id, before ids are dropped |

**Memory ownership.** `SimCompAbility`, `SimCompStats`, `SimCompVision`, `SimCompCargo`, `SimCompSummon` are allocated by `SimAbilitySystem.on_spawn` and referenced from `SimEntity` fields of the same short names (`abil`, `stats`, `vis`, `cargo`, `summon`); only this domain writes them. Grids are owned by `SimVisionSystem` and `SimAuraSystem`. Fields this domain writes in other domains' components are exactly `cc.ext_deployed`, `cc.ext_mode` (combat) and `container_id` (sim-core entity), plus lease calls. `fog_state_bytes()` returns the live array; callers must never write it. All ids crossing the API are `int` entity ids (DR-6).

`shape` is `SHAPE_DISC = 0` (`radius` in units) or `SHAPE_CAPSULE = 1` (segment `(x, y)` to `(x2, y2)` with half-width `radius`; Concealed Crossing 16 x 4 cells = segment 12 cells, half-width 2). `team_mask` has one bit per team id 0..7; with shared vision a team is a group, without it the reveal applies to every player of the masked teams. Temp-source handles are dense ints, or -1 when the 64-entry table is full. `SimWorld.fog_of_player(pid)` (ARCHITECTURE section 8) is `vision.fog_state_bytes(vision.group_of(pid))`.

## 4. Data structures & fields

All fields are `int` unless stated (DR-1). Every field listed is part of the checksum unless marked derived (section 8). `-1` is the null id.

### 4.0 Design choice: fixed slots and packed status block, not dictionaries

Facts asserted by the catalog generator: 67 of the 156 unit defs have no slot primitive, 58 have one, 21 have two, 9 have three and exactly one (Mekong Field Engineer: DETECTOR, REPAIR_ACTOR, MODE_SWITCH, AURA) has four. Research and trait grants add at most one slot to any def in shipped data (Fen gets an AURA and reaches four; Link Operator, Caravan, Bear, Gaj, Barracks, Factory and Engineer gain one each), so **6 slots** leave two spare and the validator rejects data that would exceed them. The worst simultaneous status load found in the buff analysis is 8 (two area buffs, a damage-taken buff, suppression, camouflage, cover, debris slow, EMP), so the timed-effect table has **10 entries**.

| Criterion | Fixed packed arrays (chosen) | Small `Dictionary` per entity |
|---|---|---|
| Access cost | one `PackedInt32Array` index | hash + probe, several times slower in GDScript, on every combat and movement query that needs a flag |
| Allocation | none after spawn | dictionary growth, boxing of values |
| Checksum (DR-6, DR-13) | hashed in one loop in field order, identical on every client | must extract and sort keys for every hash, or depends on insertion order, which differs if two code paths apply the same effects in a different order |
| Memory | 352 bytes for the ability comp (6 x 8 + 10 x 4 ints, x4 bytes) | roughly 1 KB with a few keys |
| Failure mode | explicit and deterministic: slot overflow is a load error, timed-effect overflow evicts the earliest expiry | silent growth |
| Cost | unused slots waste up to 190 bytes on a one-ability unit | none |

For 1680 entities the fixed layout costs 0.6 MB for abilities and statuses (only ability-bearing entities allocate it), against about 1.7 MB and a slower hot path for dictionaries.

### 4.8 `SimPlayerFx` (one per player): active global effects

If the reconciler keeps economy's knob table (`K_*`), this record becomes a read-through to `SimStrategicSystem.knob` with identical numbers (12.1). There is no SAP reserve state here (power domain).

## 5. Rules & algorithms

### 5.1 Time, rounding and cooldown conventions

* **Ticks.** 1 s = 20 ticks. JSON seconds become `ceili(s * 20)` with integer millisecond math (ARCHITECTURE section 3). Example: 6 s = 120, 4 s = 80, 3 s = 60, 2 s = 40, 8 s = 160, 12 s = 240, 15 s = 300, 18 s = 360, 45 s = 900.
* **Absolute deadlines.** All timers are absolute ticks (`t_end`, `expire_tick`, `revealed_until`). Nothing counts down per tick: conditions use absolute deadlines or combat's published counters (`still_ticks`, `last_fire_tick`, `last_hit_tick`, `ticks_since_combat`).
* **Window semantics.** An effect started during tick T with duration D covers the Combat steps of ticks T .. T+D-1 and is removed by the timer processing at the start of step 7 of tick T+D. Cooldowns are ready at `tick >= t_end`; readiness fires `EV_ABILITY_READY` from the timer wheel on that tick.
* **Basis points.** `bp` = 1/10000. Percent to bp: `pct * 100`. `muldiv_round(a, b, c) = (a * b + c / 2) / c` for `a, b >= 0, c > 0` (half-up); all intermediate products stay below 2^62 (largest: 10^6 x 10^4 x 2x10^4 = 2x10^14).
* **Distances.** Cells to units `roundi(cells * 1024)`; comparisons use squared units (`r*r`, r at most 32 cells = 32768 units, square 1.07x10^9). Vision uses cell coordinates `x >> 10`.
* **Ordering.** Every loop over entities, statuses, slots, zones or players is in ascending id or index order. `Dictionary` is never iterated in this domain (ghost and lookup tables are sorted arrays or dense arrays).

### 5.2 Effective stats, timed effects and the lease bridge

**5.2.1 Where each number lives.** The bible layers 1 to 3 are folded by `GameData`; research is `DefLayer3`; the *temporary* part of layer 4 (auras, powers, zones, conditions) is this domain's. Layer 4 is one additive layer: research and temporary deltas **add** ("+10 % research and +15 % Relay = +25 %", `data_balance.md` 5.8.2). Entries sharing a `stack_group` (or, when none, a `src_key`) count once per entity and the largest absolute delta wins.

| Data stat | Where the final number is computed | What this domain contributes |
|---|---|---|
| `HEALTH` (2), `SPEED` (3), `SIGHT` (8) | **local cache** `SimStats` | `effective = layer3.effective_unit_stat(stat, def_idx, extra_bp)` with `extra_bp` = sum over distinct stack groups of the largest delta among active timed effects, aura bits and true bound conditions |
| `DAMAGE` (4), `RANGE` (5), `RELOAD` (6) | combat (`agg_dmg_bp`, `agg_range_bp`, `agg_reload_bp`, floor 50 % of base) | leases `STAT_DMG_OUT`, `STAT_RANGE`, `STAT_RELOAD` (negative bp = faster) |
| `RESIST` (13) | combat `taken_bp` (5.6.1 of combat.md; sums add within the temporary layer, cap 50 %) | lease `STAT_TAKEN`, positive bp = less damage, `filter` from `dtype_mask` and `fire_class_mask` |
| `REARM_RATE` (15) | combat (`AIR_REARM`) | lease `STAT_REARM_RATE` on the airfield (Rapid Turnaround +5000, 400 ticks) |
| `PROD_RATE` (14) | production, through `production_rate_bp(pid, queue_kind)` | an active global effect in `SimPlayerFx` (Mobilization Order 12500 for infantry and vehicle queues); multiplied with the shortage factor, no floor (a *rate*, not a build time) |
| mark, immunity, disable | combat | `STAT_MARK` (filter = marking team bit + 256 for ground weapons), `STAT_FLAG_SUP_IMMUNE` + `clear_suppression`, `STAT_FLAG_EMP_IMMUNE`, `lock_weapons(e, until)` |

**5.2.2 Local stats.**

```
extra[k]     = sum over stack groups g of pick_max_abs(delta of contributions in g)      # distinct groups add
effective[k] = layer3.effective_unit_stat(k, def_idx, extra[k])                            # DefStatMath.effective: clamp(apply_bp(resolved, research_bp + extra), floors)
```

Worked examples: (1) Gate Guard sight 6 cells (6144 units) under Straits Crossfire `+2000`: `apply_bp(6144, 2000) = 7373` units, stamped radius `(7373 + 512) >> 10 = 7` cells. (2) Open Corridor `+2500` and Debris slow `-3500` in different groups: `extra = -1000`, speed x0.90; combat's suppression `-25 %` multiplies on top inside movement. (3) Aster jam `-2500` on `SIGHT` from group `ew_jammer`; two Asters share the group and count once. (4) Distributed Fuel Caches `+1000` speed (bound condition `OUT_OF_COMBAT 6 s`) adds to Open Corridor: `extra = +3500`.

**5.2.3 Health.** When the effective `HEALTH` changes (Circular Armor is static in `DefLayer3`; Municipal Reserves is a bound condition), `SimStats.refresh` calls `combat.rescale_hp(e, new_max)`; combat preserves the hp fraction (half-up, minimum 1) so leaving a field never heals or kills (`DefStatMath.rescale_hp`).

**5.2.4 Lease bridge (`SimLeaseBridge`).** The only translation from `DefEffect` ops to combat state:

| `DefEffect` op | Bridge call |
|---|---|
| `STAT_MOD` on DAMAGE / RANGE / RELOAD | `SimCombatMods.apply(world, e, key, STAT_DMG_OUT / STAT_RANGE / STAT_RELOAD, delta_bp, 0, ticks)` |
| `RESIST_MOD` | `apply(..., STAT_TAKEN, pct * 100, FILTER(types(dtype_mask), req(fire_class_mask), forbid), ticks)`; `fire_classes: ["direct"]` = combat's `FILTER_DIRECT_ONLY` |
| `IMMUNITY` `suppression` | `apply(..., STAT_FLAG_SUP_IMMUNE, 0, 0, ticks)` and `combat.clear_suppression(e)` |
| `IMMUNITY` `emp` | `apply(..., STAT_FLAG_EMP_IMMUNE, 0, 0, ticks)` (blocks new EMP; running EMP is combat's) |
| `DISABLE` `weapons` | `combat.lock_weapons(e, tick + ticks)` |
| `MARK` | `apply(..., STAT_MARK, damage_bonus_pct * 100, marking_team_bit \| 256, ticks)` |
| `HEAL` | not a lease: `SimStatus` schedules free healing pulses (5.7.5) through `combat.heal` |
| `CAMOUFLAGE`, `REVEAL` | `DF_CAMO_GRANTED` + `SimStealth`; `SimVision.add_reveal_entity` |
| `STAT_MOD` on SPEED / SIGHT / HEALTH | local `extra` (no lease) |

Lease keys are `FXK(src_kind, id)`. Event-driven holds (aura bit set, condition true, zone membership) use `ticks = LEASE_HOLD` and are released with `clear_key` when the cause ends; timed effects use their remaining duration so combat's own expiry matches the timed-effect expiry, and are also cleared explicitly on removal. Combat dedupes `(key, stat)` and keeps the larger absolute bp and later expiry, which implements the same-source rule; a window that raises a magnitude (Treaty 1000 to 1500) is applied with the same key, and when it ends the bridge does `clear_key` then re-applies the base magnitude to every covered entity (one pass per window event). A full lease table evicts the earliest expiry, so held leases (far expiry) outlive short ones.

**5.2.5 Recalculation triggers.**

| Event | Effect |
|---|---|
| spawn / def change | bind conditional effects, dirty all local stats, apply holds |
| timed effect applied or removed | dirty the local stats it names; apply or clear its lease |
| bound condition flips | dirty local stat or hold / clear lease |
| aura bit flips | same, for the group's effect |
| research completed (`DefLayer3.version` changed) | rebind conditional effects of the player's entities, dirty everything |
| mode change | push or clear the `RANGE +2500 / +2000` deploy lease (Charlemagne, Gaj), write `ext_deployed` |

Refresh is lazy: `SimStats.get_val` recomputes when `dirty != 0`. `SimAbilitySystem.update` never sweeps all entities.

### 5.3 Conditions: vocabulary and cheap evaluation

Conditional research effects are the `DefEffect`s returned by `DefLayer3.cond_effects_of_unit / struct` (`cond_codes`, `cond_params`). `SimCond.bind_effects` copies the indices into `stats.cond_fx` (at most 24, validator-enforced) when an entity spawns and again when research completes; each bound effect is evaluated once at binding (fresh, never assumed false).

| Code | Evaluation | Update trigger | Cost |
|---|---|---|---|
| 10 NEAR_FRIENDLY_UNIT `{radius_u, unit_ids+replacements}` | counted coverage grid per (team, condition); every living friendly entity whose def matches stamps a disc of `radius_u`; a bound recipient reads `grid.count_at(cell) > 0` | provider move / spawn / death (grid transitions flip recipient bits); recipient cell change | providers only stamp while at least one bound recipient exists in the team |
| 11 NEAR_FRIENDLY_STRUCTURE `{radius_u, structure_ids or selector, powered}` | same grid, stamped once per matching structure; with `powered` the stamp follows `power.is_powered(eid)` and `combat.is_functional` (re-stamp on power flips and EMP end) | structure spawn / death / power flip | static providers |
| 12 TARGET_NEAR_FRIENDLY_UNIT | pull, watch flag `WF_TARGET`: every 4 ticks read `cc.target_id`, test the provider grid (Wedge Recon Fighter, Watchpost, 6 cells) at the target's cell, hold or clear the RELOAD lease | 4-tick cadence | 1 array read per bound attacker per 4 ticks |
| 13 IN_RELAY_FIELD `{powered}` | bit = aura group `relay_field` covers the entity (Relays and deployed Fen masts stamp the same group) | grid transitions | O(1) |
| 14 STATIONARY `{for_t}` | pull in the watch pass: `cc.still_ticks >= for_t` (combat's counter, driven by `ext_moving`) | every second tick | 1 read |
| 15 OUT_OF_COMBAT `{for_t}` | pull: `combat.ticks_since_combat(world, e) >= for_t` (firing, being hit and dealing damage reset it) | every second tick | 1 call |
| 16 RECENTLY_DISEMBARKED `{within_t}` | `SimTransport` sets the bit on unload and schedules a wheel timer at `+within_t` | unload event | 0 |
| 17 DEPLOYED | bit written by `SimMode` when `ext_deployed` becomes 1 | mode change | 0 |
| 18 CAMOUFLAGED | `vis.concealed` | stealth change | 0 |
| 19 IN_ZONE `{zone_id}` | continuous zones set and clear the bit in their membership pass | zone pass | 0 |
| 20 STRUCTURE_POWERED | `power.is_powered(eid)`; re-check for bound structures when the owner's power state flips (polled once per tick per player) | power flip | O(bound structures) per flip |
| 1 ON_WATER | `map.is_water(cx, cy)` at cell changes (watch flag `WF_CELL`); needed only for effects data leaves runtime-evaluated (combat evaluates its own static `COND_ON_WATER` rows) | cell change | 1 lookup per crossing |
| 2 IN_CIVILIAN_GARRISON | `DF_IN_GARRISON` written by `SimTransport`; the El-Andalus +20 % is combat's static `PM_DMG_BP_GARRISON`, so no lease is needed | board / eject | 0 |

**Watch list.** `watch_list` holds only entities with `WF_STILL`, `WF_COMBAT`, `WF_TARGET`, `WF_CELL`, `WF_CLOAK` or `WF_MOVE_EVENT`: units with camouflage, bound stationary / out-of-combat / target conditions (Coordinated Barrages recipients, Fuel Caches, Outrider, Shaheen), units with pending `end_on` effects, and recipients of aura groups that need their cell tracked. Threshold conditions (`STATIONARY`, `OUT_OF_COMBAT`) are evaluated on `((tick + eid) & 1) == 0`, i.e. with at most one tick of lag; camouflage and `end_on` checks run every tick. Membership is maintained on spawn, GRANT, research completion, effect application and removal, in ascending id order.

### 5.4 Timed effects (`SimStatus`)

A timed effect is one compiled `DefEffect` op applied to one entity for a duration. Economy's power framework, zones, auras and abilities all use the same entry point; a power with several ops calls it once per op with the same `src_key`.

**5.4.1 Record.** Entity table `fx` (10 entries): `[fx_idx, src_key, expire_tick, aux]`. `src_key < 2^24` is read as a power index (economy passes `p_idx`); otherwise it is a full `FXK`. The lease key is `FXK(SRC_POWER, src_key)` or the given `FXK`.

**5.4.2 `apply_timed_effect(target_id, fx_idx, dur_ticks, src_pid, src_key)`.**

1. Resolve the entity (alive, active, not being removed) and `fx = effects[fx_idx]`; `dur = dur_ticks if dur_ticks > 0 else fx.duration_t`; a permanent effect (`dur == 0`) is not stored here (research lives in `DefLayer3`).
2. Camouflage grants are skipped for `DF_EXPOSED` entities (deployed Fen mast).
3. **Same source** = equal `(fx_idx, src_key)`: refresh, `expire = max(old, new)`, `aux = tick` (restarts the `end_on` baseline), lease re-applied (combat keeps the larger `bp`). Entries of different `fx_idx` in the same `stack_group` count once for local stats (largest absolute delta wins). Two allied casts of one power share `src_key` and therefore refresh.
4. New entry in a free slot; if all 10 are used, evict the entry with the earliest `expire` (ties: lowest index) provided the new expiry is later, else drop the new effect (returns false). Eviction fires `EV_FX_REMOVED(reason=EVICTED)`.
5. Execute the op through the bridge (5.2.4): lease, flag, local `extra` dirtying, camouflage flag, heal schedule, disable, mark; set watch flags for `end_on`; schedule wheel timer `TK_FX` at `expire`; fire `EV_FX_APPLIED`.

**5.4.3 Expiry and removal.** `TK_FX` scans the entity's table in slot order and removes entries with `expire <= tick` (release lease, dirty stats, clear flags). `clear_timed_effects(id, src_key)` removes by source. Two-phase powers (Capacitor Discharge then cooling, Software Surge then cooldown) need no chaining here: economy's scheduler applies the penalty phase (`DISABLE weapons` through `lock_weapons`) at the right tick (economy.md ask 17).

**5.4.4 `end_on` (data `end_on = MOVE | FIRE | DETECTED`).** Pull-based, no hooks:

| Event | Detection | Users |
|---|---|---|
| MOVE | `cc.ext_moving != 0` in the every-tick watch pass (movement writes it before step 7) | Silent Watch, Armored Overwatch, Field Refurbishment (per unit) |
| FIRE | `cc.last_fire_tick >= applied_tick` (stored in `aux`) | Silent Watch |
| DETECTED | vision update calls `SimStatus.remove_on_event(RE_DETECT)` for concealed entities inside a detected cell | Silent Watch |
| LOAD / OWNER | `SimTransport.board`, `on_owner_changed` | all effects on that entity |

An ended effect is removed permanently for that unit (Armored Overwatch: "moving immediately removes the bonus"; it does not return when the unit stops again).

**5.4.5 Op semantics.**

| Op | Behavior |
|---|---|
| `IMMUNITY suppression` | `STAT_FLAG_SUP_IMMUNE` hold, `combat.clear_suppression(e)` at application ("existing suppression is removed") |
| `IMMUNITY emp` | `STAT_FLAG_EMP_IMMUNE` hold; running EMP is left to combat (`combat.md` 5.8: immunity blocks new applications) |
| `CAMOUFLAGE {max_s, breaks_on}` | sets `DF_CAMO_GRANTED`; `SimStealth` reports concealed until expiry or a listed break; only for entities stationary at application |
| `HEAL` | free healing every 10 ticks: `combat.heal(world, e, gain)` with `gain_milli = hp_max * rate_bps / 20` accumulated in `heal_frac`; `cannot_fire` calls `lock_weapons(e, tick + 2)` each pulse; `ends_on_move` as MOVE above |
| `MARK` | `STAT_MARK` lease; `EV_MARKED` |
| `STAT_MOD` / `RESIST_MOD` / `DISABLE` | 5.2.4 |
| `REVEAL` on an entity | `SimVision.add_reveal_entity` |
| `SPAWN_ZONE` | `zones.spawn_zone(...)` at `initial_positions` or `target` (Broken Contact) |

### 5.5 Research, traits and grants (consumption of `DefLayer3`)

`DefLayer3` (data) stores completed research, static stat deltas, resistances, ability parameter overrides, flags and granted abilities. This domain adds only what is runtime:

1. **`on_roster_init(pid)`**: faction trait grants are already in `DefUnit.abilities` (`DefFaction.grants` applied by `DefRosterBuilder`: NAPC apron on Factory, AE salvage on Engineer); the call enables aura groups and binds nothing else.
2. **`on_research_complete(pid, r_idx)`** (after `DefLayer3.apply_research`), ascending over the player's entities: (a) instantiate `granted_abilities` into free slots (`GRANTED` flag; skipped when the kind exists; a def can exceed 6 slots only through invalid data, which the data validator rejects); (b) `SimCond.bind_effects` where `cond_effects_of_unit / struct` changed; (c) dirty local stats when `layer3.version` changed; (d) enable and stamp aura groups needed by new conditions (near friendly unit / structure, in Relay field); (e) restamp providers whose `ability_param` changed (radius: Distributed Control 6 to 8 cells, Distributed Cognition 5 to 7 cells; hold time `retain_after_power_loss_t`); (f) transports read `ability_param` at use (Rapid Ferry Drills load / unload -40 %), channels read `salvage.action_t` and `repair.rate` at use.
3. **Selectors, replacements, floors and caps** are the data domain's (`include_replacements`, `DefStatMath`); the catalog rows list, per research id, the intended ops so the data author can check `research_effects.json` against it. A replacement unit never inherits its predecessor's native abilities (bible prototype priority 7): data validates that a def's abilities come from its own row plus explicit grants.
4. **Static research effects need no code here** (Adaptive Plating, Circular Armor, Thermal Shrouds, Sensor Fusion radius, Expeditionary Maintenance, Tunnel Workshops, Standardized Parts, Buried Command Lines, Resilient Mesh, Reserve Capacitors, Dispersed Runways, Integrated Flight Decks, Predictive Maintenance, Precision Machining, Thermal Reservoirs, Recovery Winches, Rapid Ferry Drills, Watershed Logistics, Hidden Relays / Optical Mesh grants). Conditional ones are bound and evaluated per 5.3 (Joint Tactical Links, Harbor Militia, Municipal Reserves, Layered Fieldworks, Shared Fire Solutions, Coordinated Barrages, Forward Fire Control, Observer Network, Distributed Fuel Caches, Sealed Compartments).
5. **Persistence.** Completed research is never cleared; losing Radar or Laboratory changes nothing here (bible).

### 5.6 Ability runtime: commands, auto-cast, modes, channels

**5.6.1 `SimAbilitySystem.update` order (pipeline step 7).**

| b | `wheel.pop_due(tick)`: `TK_FX, TK_COOLDOWN, TK_CLOAK, TK_MODE, TK_BUILD, TK_DISEMBARK, TK_GRACE, TK_RESPAWN, TK_SUMMON, TK_WINDOW`; stale timers re-validate slot state and are ignored | due timers |
| c | Watch pass (5.3): thresholds, camouflage arming, `end_on` checks, target-near conditions, cell tracking | watched entities |
| d | Mode protocol over `mode_list` (ascending): read `cc.want_*`, advance transitions, **write `cc.ext_deployed` and `cc.ext_mode` every tick** (combat needs them before step 8) | mode-bearing entities |

**5.6.2 Commands (`SimAbilityCmds`, block 100 to 105).** Validation is identical on every client; a rejected command has no effect and produces `EV_CMD_REJECTED` for the issuing player.

| Code | Name | Fields | Effect |
|---|---|---|---|
| 100 | `CMD_DEPLOY` | `ids`, `a` slot (-1 = the unit's first deploy / sensor_mast) | request deployed mode (combat.md names CMD_DEPLOY / UNDEPLOY / SET_MODE as abilities' commands) |
| 101 | `CMD_UNDEPLOY` | `ids`, `a` slot | request mode 0 (pack time applies) |
| 102 | `CMD_SET_MODE` | `ids`, `a` slot, `b` mode index, `-1` = cycle | mode_switch kinds (Raptor, Shinano, Protea) |
| 103 | `CMD_USE_ABILITY` | `ids`, `a` slot, `b` op (0 start, 1 cancel or pack), `c` target eid or -1, `x,y` point or -1 | portable_cover, decoy_spawn, sensor_puck, smoke_launcher (build then zone), repair / salvage / capture (`SimChannel.begin` with target `c`) |
| 104 | `CMD_SET_AUTOCAST` | `ids`, `a` slot, `b` 0 / 1 | writes `AUTOCAST` where 5.6.3 allows |
| 105 | `CMD_UNLOAD` | `ids`, `a` 0 all / 1 one, `b` passenger eid, `x,y` drop point or -1 | `SimTransport.begin_unload` |

**5.6.4 Mode protocol (`SimMode`: deploy, sensor_mast, mode_switch, submerge).** Combat and abilities communicate only through `SimCompCombat` fields.

* Combat writes `cc.want_deploy` (1 deploy, 0 pack, -1 none), `cc.want_mode` (mode index or -1), `cc.want_surface` (1 / 0 / -1) as *levels*: it rewrites them every tick it needs them, and this domain never clears them.
* This domain writes, every tick before step 8: `cc.ext_deployed` (1 only while fully deployed, 0 while packing, transitioning or mobile) and `cc.ext_mode` (current stable mode index, **-1 during a transition**, so no weapon set fires while switching).
* **Transition**: request accepted if the unit is functional, not in a container, not already transitioning, and (for `switch_at_structure_id`, Raptor loadout) on a matching pad (`orders.on_pad`). `t_end = tick + deploy_t / pack_t / switch_t` from `ability_param` (Mobile Dispatch: Saker `pack_t` 0; Predictive Maintenance: Shinano 3 s to 2 s); `DF_IMMOBILE` from the request tick until done (and after, when `immobile`), `EV_MODE_STARTED`.
* **Completion** (`TK_MODE`): `ext_deployed = 1`; hold leases `RANGE range_bonus_bp` and `DAMAGE damage_bonus_bp` (key `FXK(6, ab_idx)`): Charlemagne +2500, Gaj +2000; `DF_TURN_LOCKED` if `turn_locked`; deployed-only auras become active with `command_radius_bonus_u` (Long Command Walker +2 cells); `sensor_mast`: detector radius becomes `reveal_radius_u` (Fen 6 cells) and `DF_EXPOSED` (requested amendment `exposed = true`: camouflage locked, immune to Silent Watch and Optical Mesh); `EV_MODE_CHANGED`. Pack reverses all of it and sets `ext_deployed = 0` at once.
* **Numbers**: Paladin 60 ticks deploy and pack; Archer 80; Ibex 40; Saker 20 (0 pack with Mobile Dispatch); Fortress Guard 60; Long Command Walker 60; Mekong 40 before its command field starts; Charlemagne and Gaj 80; Ifrit 60; Fen 40; Shinano 60 (40); Protea 60; Fjord 30.
* **Submerge (Boreal)**: `want_surface == 1` while SUBMERGED starts SURFACING (`transition` 20 ticks*, concealment ends immediately, layer unchanged so only anti-submarine weapons can still hit it); at completion `world.set_layer(e, SURFACE)`, state SURFACED with `t_end = tick + surface_t` (160), refreshed on every tick with `want_surface == 1` (so the sub stays up 8 s after its last need to fire); at `t_end` DIVING for `transition`, then `set_layer(UNDERWATER)` and concealed again. Detectors reveal a submerged sub through the normal detection rule; strategic blasts hit all layers (combat data).

**5.6.5 Channels (`SimChannel`): repair, salvage, capture.** Order handlers (economy / orders) walk the actor into range and call `begin(world, e, slot, target_eid)`; the channel validates the target (kind tags, friendly or neutral rules, `can_self`, `one_target`, range) and runs until the target is gone or out of range 20 ticks, the actor moves (salvage, capture) or is re-ordered.

* **Repair pulse** every 10 ticks: `rate_eff = rate_bps * (10000 + repair_bonus) / 10000` where `repair_bonus` comes from `ability_param` after research (Expeditionary Maintenance, Tunnel Workshops for `defense` targets, Modular Servicing) and roster modifiers (`repair_progress_rate` for structures); `gain_milli = target.hp_max * rate_eff / 20`; paid repair costs `paid_cost * cost_bp * rate_eff * (10000 + cost_bonus) / (rate_bps_base * 10000 * 20)` milli-credits, whole credits via `economy.try_spend(pid, 1)` from `repair_frac` (Standardized Parts -15 %, AE -25 % are `cost_bonus` folded by data into `repair_cost_bp`); heal via `combat.heal(world, target, hp)`; nothing heals when a credit cannot be paid; `cost=free` skips payment (Lagos drone). Example: 1000 hp / 1000 credit tank, base: 5 hp and 2.5 credits per pulse, 100 hp and 50 credits per 200 ticks; with Standardized Parts 2.125 credits per pulse.
* **Salvage**: target must satisfy `combat.wreck_can_be_salvaged_by(world, wreck, pid)`; after `action_t` (160; Recovery Winches 100; Recovery Priority window 60) call `combat.try_salvage(world, wreck_id, pid, payout_pct)` (20 %), returns the credits (or -1), then `economy.add`; `EV_SALVAGE_DONE`.
* **Capture**: after `capture_t` (10 s*) `world.change_owner(structure, pid)`; targets are neutral structures whose `DefNeutral.capturable` is true (Engineer only; enemy production and superweapon structures are never capturable).

**5.6.6 Disembark buffs (`disembark_buff`, Joint Landing window).** On the unload event `SimTransport` calls the hook: if `tick < abil.disembark_until` nothing happens ("reboarding cannot refresh"); otherwise `disembark_until = tick + duration_t` and the ability's ops are held as leases for `duration_t`: Island Raider `DMG_OUT +2000`, River Marine `TAKEN 2000 (all weapon types)`. While the Joint Landing global effect is active the same hook applies Joint Landing's `TAKEN 2000` for 120 ticks with its own key. Condition 16 (RECENTLY_DISEMBARKED) reads the same timestamp.

**5.6.7 Spawn abilities (`portable_cover, decoy_spawn, sensor_puck, smoke_launcher`).** `CMD_USE_ABILITY`: READY, gates (`stationary_only` requires `cc.still_ticks >= 1`; `max_active_n` / `pieces_per_builder_n`), then BUILDING for `build_t` (`DF_BUSY`, immobile), then `zones.spawn_zone(zone_idx, pid, x, y, angle, until, bind)` at the unit (or target), state ACTIVE with `aux0 = zone id`, and at zone end COOLDOWN for `cooldown_t`. A move order on a builder with `pack_t > 0` goes through `request_pack` (state PACKING, `DF_IMMOBILE`, zone removed at the end); a new cover from the same builder ends the previous piece. Numbers: Vanguard cover build 80, pack 40, life 900, one piece; Sapper and Combat Pioneer build 80, life 900; Alpine shelter life 900, 25 %; Naga smoke radius 4 cells, 120 ticks, cooldown 800; Civic puck 400 ticks, cooldown 600; Echo decoy tank 600 ticks, cooldown 800, one active.

### 5.7 Auras, command fields, Relay and free healing (`SimAuraSystem`)

**5.7.1 Model: counted coverage grids per team and `stack_group`.** Every aura-type ability (`command_field, relay_field, aura_regen, heal, suppression_support, ew_jammer, spotter`) and every research condition of type "near friendly unit / structure" has a `stack_group`. For each (victim team, group) there is one `SimCoverGrid` (byte counts, allocated on the first stamp). A recipient is covered iff `grid.count_at(cell) > 0`, so overlapping providers of one group never stack (bible "fields do not stack"; `stack_group` in the registry), and different groups are independent bits in `aura_bits`.

* **Provider active** iff alive, not in a container, `combat.is_functional(world, e)` (EMP shutdown and unpowered structures switch fields off), `power.is_powered` where `powered_required`, not `combat.is_suppressed(e)` for suppressible providers (Link Operator, Signal Officer, Mekong: "destroying or suppressing the provider removes its field"), and `requires_deployed` satisfied (`cc.ext_deployed == 1`). Power grace: a `powered_required` provider that loses power stays active until `t_end = tick + retain_after_power_loss_t` (Distributed Control: 200 ticks) via `TK_GRACE`; destruction ends it immediately.
* **Stamp** radius `r_cells = (radius_u + 512) >> 10`, with `radius_u` from `ability_param` (research: Relay 6 to 8 cells, command field 5 to 7 cells), plus the active Reserve Bandwidth global effect (`command_field.radius_cells` add 3) and the deployed bonus `command_radius_bonus_u`. Friendly groups stamp into the owner's team grid (allies share it); enemy-scope groups (`ew_jammer`) stamp into every other team's grid. Moving providers call `move_disc` when their cell changes.
* **Transitions**: `SimCoverGrid` reports 0 <-> positive cell changes to `SimAuraSystem.on_cell(team, group, cell, positive)`; for each entity in that cell (spatial hash, ascending id) of the matching team whose def is an eligible recipient the handler sets or clears the group bit and holds or releases the group's effect (lease or local `extra`). An entity that changes cell re-reads its groups (`WF_CELL`). Spawn evaluates the same way.
* **Magnitude** comes from the ability params and windows: Relay `damage_bonus_bp` 1000 (the Treaty Coordination global effect sets 15 %), command field 1000 (Central Priority sets 20 %). When a window opens or closes the bridge re-issues the group's lease to all covered entities of the team (`clear_key` then apply; one pass per window event). With allied providers the team magnitude is the maximum of its players' windows.

The "artillery spotter" roles carry no other numeric effect (section 12.1, item 1).

### 5.8 Stealth, camouflage and detection (`SimStealth`)

**5.8.1 Concealment.** An entity is *concealed* when any of the following holds, `DF_EXPOSED` is clear and `tick >= revealed_until`: a `camouflage` slot is CLOAKED (natural or research-granted: Optical Mesh, Hidden Relays), `DF_CAMO_GRANTED` (Silent Watch timed effect), or a `submerge` slot is SUBMERGED. `DF_EXPOSED` comes from a deployed `sensor_mast` (requested amendment `exposed = true`): the deployed Fen mast is "visibly exposed", i.e. immune to every camouflage source. Whenever the result changes `SimStealth` writes `vis.concealed`, fires `EV_CLOAK_CHANGED`, and asks the vision system to recompute the entity's mask for all groups immediately (5.9.6).

**5.8.2 Camouflage arming (pull-based).** Registry params: `delay_t`, `needs_stationary`, `needs_no_attack` (default true), `moving_ok`, `reveal_on_fire`, `reveal_on_damage`, `reveal_t`, `keeps_abilities_active`. The slot's `t_end` is the earliest tick at which the cloak may (re)engage; combat publishes the timestamps, so no hooks are needed. Entities with a camouflage slot are on `WF_CLOAK` and evaluated **every tick**:

```
on slot creation (spawn or grant):   t_end = tick + delay_t ; state = ARMING          # a fresh unit is never instantly cloaked
lf = cc.last_fire_tick ; lh = cc.last_hit_tick                                          # published by combat; at most one tick old in step 7
if reveal_on_fire and lf > aux0:     t_end = max(t_end, lf + delay_t) ; aux0 = lf ; decloak
if reveal_on_damage and lh > aux1:   t_end = max(t_end, lh + max(delay_t, reveal_t)) ; aux1 = lh ; decloak
channel work (repair, salvage) by a unit with reveal_on_work: t_end = tick + delay_t ; decloak      # SimChannel writes it directly
still_ok = (not needs_stationary) or cc.still_ticks >= delay_t                          # moving resets combat's still_ticks, so re-arming needs delay_t quiet ticks
cloaked  = tick >= t_end and still_ok            -> state CLOAKED / ARMING
```

Detection is not an arming violation: the bible reveals a camouflaged unit *within* a detector radius and it hides again when the detector is gone. For Dune Rover `reveal_t = 120`: while detected the vision update sets `revealed_until = max(revealed_until, tick + reveal_t)` ("detection reveals it for 6 seconds").

|---|---|---|---|---|---|
| Condor Stealth Bomber | 120 | no | yes | 0 | cloaks while flying; 6 s after its last attack |
| Mirage Observer, Watchpost Recon Team | 120 | yes | no | 0 | |
| Canopy Ranger | 120 | yes | no | 0 | any terrain |
| River Warden | 120 | yes | no | 0 | `reveal_on_work`: repairing or salvaging reveals |

| Caravan APC (Optical Mesh grant) | 120 | yes | no | 0 | Dune Rover keeps its own slot |

| Silent Watch (timed effect, not a slot) | 0 | applied to units stationary at cast | | | up to 300 ticks; ends on move, fire, detection (5.4.4) |

**5.8.3 Submarines.** State machine in 5.6.4 (`want_surface` protocol). Bible mapping: "camouflage underwater and surface for 8 seconds when firing" = SURFACED window `surface_t` 160 after the last `want_surface`; "detectors reveal them" = ordinary detection while SUBMERGED; "only anti-submarine weapons can target them underwater" = combat's layer filters (`TF_UNDERWATER`); "strategic blast damage still applies" = combat's strategic area damage; a surfaced submarine is an ordinary surface target.

**5.8.4 Detection.** `detector` slots (units and structures) stamp the owner group's `det` grid with a disc of `(detect_radius + 512) >> 10` cells where `detect_radius` is `DefUnit.detect_radius` after `ability_param` (Sensor Fusion +2 cells on Surveyor, Rapier, Horizon Escort and replacements). Radii: default 5 cells (5120 units), Watchtower 4, AA battery 5, deployed Fen mast 6. Detector structures of type `defense` are active only while `power.defense_online(pid)` and functional (economy 5.7: powered defenses and their detector radius stop in a shortage, sight does not). Reveal zones and temp sources with `detect = true` (UAV Sweep, Survey Drone, Maritime Patrol, Recon Balloon, Wideband Scan) stamp the same grid; sensor pucks, Long Watch and Survey Network reveal terrain and ordinary units but do not detect.

**5.8.5 Visibility predicate.** For group `g` and an entity `en` of another group: `seen(g, en) = active(en) and vis[g][cell(en)] > 0 and (not concealed(en) or det[g][cell(en)] > 0)`. Fog and detection compose as the bible says: a detector reveals concealed units inside its radius, but only where the group can see the cell at all. `vis_mask` bit `g` stores the result; the owner group bit is set whenever the entity is active. Entities flagged `EF_NO_VISION_GRANT` never reveal fog for their owner.

**5.8.6 Decoys (Echo Team tank, False Convoy, False Front, Feint Landing).** Decoys are temporary entities (`EF_DECOY | EF_TEMPORARY | EF_NO_SALVAGE | EF_NO_CAPTURE | EF_NO_REPAIR`, 1 hp, no weapons, no collision) created by zones or by economy's decoy recipe. To enemies they look like the unit they imitate. A decoy is *identified* for group `g` when `det[g][cell] > 0`; the first identification fires `EV_DECOY_IDENTIFIED`, and `SimVision.decoy_identified` makes combat exclude it from automatic acquisition (explicit attack orders still work; one hit kills). Decoys never count toward victory, unit cap or salvage.

**5.8.7 Interplay with combat.** Firing, taking damage and (for stationary cloaks) moving reveal, as in `rule.combat.concealment_and_electronic_warfare`. Combat calls `SimVision.can_see(world, pid, e)` for acquisition (`is_known` also for orders on remembered structures); splash still hits concealed units. A unit that becomes concealed loses its acquisition at the next scan; projectiles in flight continue. Structures are never concealed. Roster fairness (test 10.5): every roster has a T1 detector unit reachable without a Dock, every T2 ship escort carries `detector`, and Watchtower / AA battery have detector radii 4 and 5, so no camouflage opening is uncounterable.


### 5.9 Fog, shroud and vision (`SimVisionSystem`, pipeline step 10, stride 2 or 3)

**5.9.1 Decisions.** No height occlusion: sight is a cell-granular disc that ignores terrain height, forests and buildings. Cell states per group: 0 shroud (never seen), 1 fog (explored, not currently visible), 2 visible. Shroud never returns. Fog can be disabled by `MatchRules.fog = false` (all states 2, all masks full, `update` returns immediately).

**5.9.2 Groups.** `group_of(pid)`: with shared vision (default for allies) group = index of the player's team in ascending team-id order, otherwise group = pid. At most 8 groups. Teammates' sources stamp the same grids, so explored area and vision are shared without any per-pair logic. Neutral entities have `group = -1` and never act as sources, except an occupied garrison building (below).

**5.9.3 Sources.**

* Every entity with `STAT_SIGHT > 0`, active (not in cargo, not being removed), is a source. Radius `R = clamp((sight_u + 512) >> 10, 1, 32)` cells around its own cell `(x >> 10, y >> 10)`. Air units use the same disc. Structures under construction use `min(R, 3)` until complete.
* Disc shape: cell `(dx, dy)` is inside iff `dx*dx + dy*dy <= R*R`; the row half-width table is `hw[R][dy] = isqrt(R*R - dy*dy)` (built once with `Fp.isqrt`, exact), 33 x 65 ints.
* An occupied civilian garrison building becomes a source for the occupying group with `sight_u = max(sight of occupants)`; it reverts to no source when empty.
* Temporary sources (table of 64): disc or capsule (segment plus half-width), optional detection, absolute `until_tick`, optional bound entity (the source ends when it dies), a team mask. Created by `SimVision.add_reveal` (economy's reveal powers, sensor pucks) and by zones of kind REVEAL; entities flagged `EF_NO_VISION_GRANT` never act as sources for their owner.

**5.9.4 Incremental update (every `stride`-th tick, default 2: `tick % stride == 0`).**

```
1. for eid in pending_restamp (ascending): unstamp old disc, stamp new disc        # spawn, sight stat change, owner change
2. for eid in movers (ascending; non-static sources):
      (cx, cy) = (x >> 10, y >> 10)
      if (cx, cy) != stamped: move_disc(old -> new)  ; mark entity cell_changed
3. detectors: same loop on the det grids (only entities with a DETECTOR slot)
4. temp sources: expire (until <= tick) or follow body; stamp/unstamp
5. transitions (count 0 <-> positive) were recorded by SimCoverGrid into changed_cells[g]
6. entity masks: for each changed cell: for each entity in that cell (ascending id): recompute bit g of vis_mask
                 for each cell_changed mover: recompute all group bits
7. bit changes: update ever_mask, fire EV_VIS_CHANGED (event groups only), create/remove ghosts
8. every 10 ticks: drop ghosts whose cell is currently visible
9. bump fog_ver[g] for groups with any transition ; update digests
```

Step 2 is throttled by `restamp_budget` per update with an eid-ordered deferral ring (section 9.2), and the update runs every `stride`-th tick (`MatchRules.vision_stride`, 2 by default). `move_disc(old, new, r)` works row by row: for each row `dy` the old span `[a0, a1]` and new span `[b0, b1]` are compared and only `b \ a` is incremented and `a \ b` decremented, so a one-cell step costs about `2 * (2R + 1)` array writes (34 for R = 8) instead of 2 x 200. A radius change (sight buff) is an unstamp plus stamp. Counts use `PackedInt32Array` (a shared-vision team can pile several hundred sources over one cell).

**5.9.5 Fog output.** `fog[g]` (`PackedByteArray`, `w*h`) is updated on the same 0 <-> positive transitions: `0 -> positive` sets 2 (first time also counts as explored: `explored_digest ^= zob2(cell)`), `positive -> 0` sets 1. `fog_state_bytes(g)` returns it directly; `fog_version(g)` increments once per update that changed anything so the view uploads its L8 texture (at most 64 KB) only then. The minimap reads the same array (explored = state >= 1). Nothing in the sim reads the texture.

**5.9.6 Entity visibility mask.** `vis_mask` bit `g` is `seen(g, en)` from 5.8.5. Own-group bit is set while active. The masks are recomputed only (a) for entities inside cells that changed state, (b) for entities that changed cell, (c) when concealment changes (immediate, all groups), (d) when an entity is spawned or its owner changes. Combat therefore always reads a mask that is at most one tick stale for pure fog changes (stride 2) and exact for stealth changes.

**5.9.7 Remembered structure ghosts.** When bit `g` of a non-neutral, non-own structure turns from 1 to 0 and `ever_mask` bit `g` is set, group `g` gets a `SimGhost` (`def_idx, owner, x, y, facing, hp_pct, seen_tick`) replacing any previous ghost of the same eid (sorted array by eid, binary insertion). While the structure is visible its ghost is removed (`EV_GHOST_REMOVED`). A ghost also disappears when its cell becomes visible and no structure is seen there (destroyed while unseen), checked every 10 ticks. Ghosts are display and pathing memory only: `SimVision.is_known` is true for a ghost so attack orders on a remembered structure are accepted, but combat only fires at entities for which `can_see` holds. Units are never ghosted.

**5.9.8 Temporary vision and powers.** `SimVision.add_reveal(team_mask, shape, x, y, x2, y2, radius, until_tick, detect, bind_ent)` wraps `add_temp_source` for every team in the mask (with shared vision a team is one group; without it every player of the team). It is used by economy's REVEAL_ZONE and RECON_SUMMON powers (UAV, Survey Drone, Recon Balloon and Maritime Patrol bind the source to their shootable body: `bind_ent` dead removes it), by Wideband Scan after its 40-tick warning, and by zones of kind REVEAL. Counterbattery Solution reveals enemy artillery through `add_reveal_entity` (a `revealed_until` on those units, not a source). Reconnaissance powers may target any map location; other powers need `is_visible`; superweapons and decoys need `is_explored`; revealing terrain marks it explored permanently.

**5.9.9 Events.** `EV_VIS_CHANGED(eid, group, seen)` only for groups in `set_event_groups(mask)` (the local player's group in real games, 0 in headless runs; it never influences sim state, DR-12). `EV_GHOST_ADDED / EV_GHOST_REMOVED`. Audio and UI derive "unit spotted" and "structure discovered" from these; the view derives fog textures from `fog_state_bytes`.

**5.9.10 Cost summary (details in section 9).** Five facts: (1) cost is proportional to *cell crossings*, not to sources; (2) structures stamp once; (3) a step of one cell costs about 34 writes at R = 8; (4) entity-mask work is proportional to transitions, not to entities x groups; (5) 8 groups use 8 x (256 + 256 + 64) KB = 4.5 MB at 256 x 256.

### 5.10 Transports, cargo and garrisons (`SimTransport`)

**5.10.1 Capacity (bible `rule.combat.transports_aircraft_and_repairs` and unit texts) as registry `transport` params.** Capacity is counted in slots: an infantry squad (any infantry entity, Engineers included) uses 1; a non-amphibious land vehicle uses `capacity_squads_n / capacity_vehicles_n` slots (2 in a Landing Transport).

| Carrier | `capacity_squads_n` / `capacity_vehicles_n` | Accepts | Excluded | Load / unload per squad (ticks) | Notes |
|---|---|---|---|---|---|
| Combat APCs: Pathfinder, Surveyor, Caravan, Mule, Wake Skimmer, Jade Carrier, Mamba, Jackal, Beaver, Fen, Dune Rover, Steppe, Kancil, Lotus, Naga | 2 / 0 | infantry | everything else | 10 / 10 (`unload_speed_bp` 15000 on Kancil gives 7; Rapid Ferry Drills -40 % gives 6 / 6 on Naga) | `passengers_fire = false`; Beaver `passenger_damage_reduction_pct` 50 |
| Okapi Amphibious Carrier | 3 / 0 | infantry | | 10 / 10 | Watershed Logistics: `regen target=passengers` 1 %/s after 120 ticks out of combat; the carrier is not healed |
| Leviathan Assault Carrier | 4 / 0 | infantry | | 10 / 10 | |
| Landing Transport (service) | 4 / 2 | infantry or non-amphibious land vehicles | transports, MCV, amphibious vehicles (`excluded_unit_tags`) | 10 / 10 | 4 squads, or 2 vehicles, or 1 vehicle + 2 squads |
| Civilian garrison (neutral, marked) | 4 / 0 | infantry | vehicles | 10 / 10 | `garrison_fire = 1` (5.10.5) |

Times come from `ability_param` (`load_t`, `unload_t`, `unload_speed_bp`), so research and unit variants apply.

**5.10.2 Boarding and unloading.**

* `can_board(carrier, pax)`: both alive, pax not in a container, same team (or an unclaimed / own-claimed neutral garrison), class allowed, exclusions clear, `used_slots + slots(pax) <= cap_slots`.
* `board` is instant: `pax.container_id = carrier`, the passenger leaves the spatial hash and vision stamping, its order is cleared, `end_on LOAD` effects end, its position mirrors the carrier each tick (`AbilitySystem` step 7e). Orders walk the passenger to within 2 cells first. The carrier stays `DF_IMMOBILE` until `tick + load_t`.
* `begin_unload(mode, pax, x, y)`: legal if the carrier is stationary (`cc.still_ticks >= 1`) or has `DF_UNLOAD_MOVING` (Mobile Reserve: `unload_moving_speed_bp` = 5000, carrier speed x0.5 while unloading). One passenger leaves every `unload_t` ticks in load order.
* **Exit cell**: from the requested point (default the carrier's cell) search rings 1..3; ring `r` is scanned east first, clockwise, `8r` cells; the first cell passable for the passenger's `move_class` (`map.passable`) with fewer than 4 entities of its layer wins. Non-amphibious infantry never exit onto water; amphibious passengers may. No cell: `EV_UNLOAD_BLOCKED`, the passenger stays.
* On exit: `container_id = -1`, spatial hash insert, vision restamp, `EV_UNLOADED`; this triggers the disembark hook (5.6.6) and sets `RECENTLY_DISEMBARKED`.

**5.10.3 Amphibious cargo.** Cargo is independent of terrain: any legal passenger may ride an amphibious carrier over water. Landing Transport vehicle cargo is limited to non-amphibious vehicles because amphibious ones can swim.

**5.10.4 Container death (combat drives, this domain executes).** Combat's death profile decides `CARGO_DIE`, `CARGO_EJECT_HURT` or `CARGO_EJECT` (combat.md 5.11) and calls `SimTransport.eject_all(world, container, hp_loss_bp)`. Default for transports and garrisons is EJECT_HURT with `eject_loss_bp(container)` = 4000 (Beaver: 4000 x (100 - 50 %) = 2000), garrison 3500*. Passengers appear at exit cells (5.10.2), lose `hp_loss_bp` of *max* health (never below 1 hp), and a passenger with no legal cell within ring 3 (non-amphibious over deep water) dies through `combat.kill(CAUSE_CARGO)` (drowned). A carrier that is sold or consumed unloads normally with no loss.

**5.10.5 Civilian garrisons.** A garrison is a neutral map structure (`DefNeutral.garrison_squads` 4) with a transport slot. The first squad to enter sets `claim_team`; other teams cannot enter while it is claimed; the claim resets when the last squad leaves. Occupants fire from the building position when the def has `garrison_fire = 1` (combat gate 1), are not individually targetable, and area damage hits the building only. `garrison_claim_team` makes the building hostile to enemies of the claim team and auto-targetable only while claimed. Garrisoned infantry have `DF_IN_GARRISON` (condition 2); El-Andalus's +20 % is combat's static `PM_DMG_BP_GARRISON`. An occupied garrison acts as a vision source for the claiming group (sight = max occupant sight). Garrisons are not capturable.

**5.10.6 What rides where (validator, from the catalog).** `transport` on exactly the 18 transport-tagged units (15 APC-class units plus Okapi, Leviathan, Landing Transport); the Landing Transport is the only vehicle carrier; only Okapi, Leviathan and Landing Transport carry more than 2 squads.

### 5.11 Zones (`SimZoneSystem`, pipeline step 9)

Zones are a generic runner for the data templates of `zones.json` (`DefZone`: `zone_kind, shape, radius, length, width, duration_t, affects, follow_source, hp, target_mask, visible_to_enemy, max_per_owner, effects[]`). Behavior lives in the template's `effects[]` (ops of `data_balance.md` 7.5); only kinds with special mechanics have code.

**5.11.1 Lifecycle.** `spawn_zone(zone_idx, pid, x, y, angle, until_tick, bind_eid)`:

1. Enforce `max_per_owner` (the owner's oldest zone of that template ends first; a builder's new cover replaces its old one).
2. Allocate the lowest unused id (monotonic counter, never reused); `t_start = tick`, `t_end = until_tick` or `tick + duration_t`; `state = WARMUP` when the template or caller specifies a warning (Wideband Scan 40 ticks), else ACTIVE. A full table (96 zones) returns -1 (`PW_ERR_LIMIT` for callers).
3. `hp > 0` spawns a shootable body through `SimSummons` (pontoon, drone station, sensor puck, balloon; `SM_SHOOTABLE`); body death ends the zone (`EV_ZONE_ENDED` reason 1). `follow_source` moves the zone with `bind_eid`; a zone bound to an entity ends when it dies.
4. Kind REVEAL opens a temporary vision source (5.9.8); DECOY spawns its decoys (below).
5. `EV_ZONE_SPAWNED`. At `tick >= t_end` (or body death, cancel) the zone releases leases and timed effects it applied, closes its vision source and fires `EV_ZONE_ENDED`.

**5.11.2 Membership and effects.** Membership passes run every 4 ticks for SMOKE, COVER, SHELTER and DEBRIS and every 10 ticks for REPAIR. Shapes: `CIRCLE` (`SimShape.circle_contains`) or `LINE` = capsule (segment centered at `(x, y)` with the given `angle` and `length`, half-width `width / 2`, `capsule_contains`). Candidates come from `SimShape.query_shape` (ascending ids, at most 64 members; excess ignored deterministically). A member is an active entity whose relation to the owner matches `affects` (friendly, enemy, all) and the effect's `selector`. For each effect op the pass holds a lease or timed effect with `src_key = FXK(5, zone_idx)` and duration `2 x period`; entities that left the member list since the previous pass are released immediately. `membership = latched` zones (BUFF) apply once at creation and never re-evaluate.

**5.11.4 Trident (hand-off with combat, combat.md 5.7).** Up to 8 INTERCEPT zones occupy `inter_slots`; each has `charges` (24), an owner team and a circle.

```
intercept_ordinary(world, owner_team, x0, y0, x1, y1, sx, sy, proj_flags):   # combat calls once per PF_ZONE_INTERCEPTABLE projectile per tick, when n_intercept > 0
    for slot in 0..7 ascending: z = zone(inter_slots[slot])
        if z == null or z.team == owner_team or z.charges <= 0 or circle_contains(z, sx, sy): continue      # launch point inside bypasses
        if segment_enters_circle(z.x, z.y, z.radius, x0, y0, x1, y1):                                          # swept: start outside, segment meets the circle
            z.charges -= 1 ; return z.id                                                                       # combat removes the projectile, emits EV_INTERCEPT
    return -1

intercept_packet(world, owner_team, x, y):                                    # combat calls once per strategic packet at detonation
    for slot ascending: z hostile, z.charges >= 8, circle_contains(z, x, y): z.charges -= 8 ; return 5000        # added to combat's temporary resistance layer, 50 % cap still binds
    return 0                                                                # fewer than 8 charges cannot reduce; a packet is never cancelled
```

Rules honored: ordinary hostile missiles and shells (`PF_ZONE_INTERCEPTABLE`) crossing inbound each cost 1 charge and are destroyed; beams, bullets, hitscan, EMP strikes (Aurora), Helios sweeps and units entering the zone are never asked; weapons fired from inside (`sx, sy`) bypass; a superweapon packet (each Atlas rod, Perun core and ring, Horizon impact, Tempest drone hit, Dragonfall engine shot) costs 8 charges for -50 % and never cancels. Ledger for 24 charges: 5 shells leave 19; packets 1 and 2 are reduced (3 left); packet 3 is full damage. The zone is fixed, drawn for every player, active 500 ticks after the 6-second warning; it stays inert but visible at 0 charges.

**5.11.5 Warnings.** Economy's `SimWarning` is the attack record (timeline, `affected_mask`, payload); `zones.spawn_warning(kind, pid, x, y, angle, a, b, ticks)` mirrors it as a zone so the view has one renderer. The marker is visible to the owner team and to every player owning an entity inside the shape expanded by 3 cells (recomputed every 10 ticks), independent of fog and decoys.

**5.11.6 Bodies and targets.** Zone bodies (UAV, drone, pontoon, station, puck, balloon, cargo aircraft) are entity defs from the balance layer (`summon.*` in economy's `summons.json`), flagged `SM_SHOOTABLE | SM_TEMPORARY`; they are excluded from unit caps, victory and salvage, and targeted by AA or ground weapons under the ordinary rules.

### 5.12 Summons and temporary units (`SimSummons`)

Economy adopts this primitive for Tempest drones, Dragonfall capsules and engines, UAVs and other recon bodies, decoys and stations (`economy.md` 12.1 M6); combat supplies the entity flags it needs (`CF_SUMMONED`, `CF_ENEMY_ONLY`, `CF_DECOY`). `SimSummons.spawn(world, def_idx, pid, x, y, parent_eid, flags, life_ticks, driver, ax, ay, ar)` creates the entity through `world.spawn_entity` (spawn flag `F_NO_UNIT_CAP` for `SM_TEMPORARY`), attaches `SimCompSummon`, sets `SimEntity.expire_tick`, schedules `TK_SUMMON` (which calls `combat.kill(CAUSE_EXPIRE)`; no wreck) and calls `on_spawn`. **8.2 What enters the checksum** (folded at the end of tick when `tick % 20 == 0`; entities ascending). `SimStats.refresh` is forced first so hashed values never depend on lazy timing.

* Per entity: `SimCompAbility` (slots, `fx` table, `cond_bits`, `aura_bits`, `watch`, `last_cell`, `spawn_tick`, `heal_frac`, `repair_frac`, `granted_mask`, `tn_target`, `disembark_until`), `SimCompStats` (`vals`, `extra`, `flags`, `hp_max_last`, `l3_version`, `cond_fx`), `SimCompVision` (all fields), `SimCompCargo` (all), `SimCompSummon` (all). Leases live in combat's component and are hashed by combat (`combat.hash_into`).
* Global: every `SimZone` (ascending id, all fields and `members`), `next_zone_id`, `inter_slots`, the temp-source table, per group `vis_digest / det_digest / explored_digest`, each ghost list, per team and group the aura grid digest, `timer_digest` (rolling FNV over fired timers `(tick, eid, kind)`), each `SimPlayerFx` (`active`).
* Not hashed (derived, reconstructible): raw wheel buckets, `watch_list`, `active_list`, `mode_list`, `providers`, `heal_members`, `fog` byte arrays and `fog_ver`, scratch arrays.

**8.3 Zobrist digest.** `zob(cell) = mix32(cell * 0x9E3779B1 + 0x7F4A7C15)`, `mix32(v)`: `v ^= v >> 16; v = (v * 0x7FEB352D) & 0xFFFFFFFF; v ^= v >> 15; v = (v * 0x846CA68B) & 0xFFFFFFFF; v ^= v >> 16`. A grid digest is XORed with `zob(cell)` whenever a count changes between 0 and positive; explored uses `zob2(cell) = mix32(cell ^ 0x85EBCA6B)` once per cell. All arithmetic is masked to 32 bits inside 64-bit ints.

**8.4 Order-dependent hazards.** (1) `on_remove` runs in CleanupSystem in ascending eid before ids are dropped; (2) stamp transitions fire in row-major cell order; (3) ties between zones or providers go to the lower id everywhere; (4) `SimMode` writes `ext_deployed / ext_mode` every tick in step 7 so combat at step 8 sees the same values on every client; (5) Packed arrays store int32, so ticks and counts stored in them must stay below 2^31 (20 TPS x 100 h = 7.2x10^6).

### 9.1 Vision cost analysis (8 players)

* Cost is proportional to *cell crossings*, not to sources or to map size. A unit moving 3 cells/s crosses a cell every 6.7 ticks (0.15 crossings per tick, 0.3 per vision update).
* A one-cell step in x or y runs specialised edge code: x steps write 2 cells per row (17 rows at R = 8, 34 writes), y steps write two rows (34 writes). About 190 statements including transition checks; diagonal steps cost about 1.6x.
* Transition work: about 5 of the 17 leading-edge cells per crossing change state (the others are already covered by other sources); each transition visits the entities in that cell (about 20 statements).
* Memory: per group `vis` 256 KB + `det` 256 KB + `fog` 64 KB = 576 KB; 8 groups = 4.6 MB; aura grids 64 KB each, three classes for four teams = 0.8 MB; components about 1.3 MB. Total under 8 MB.
* Shared vision (2 to 4 groups instead of 8) divides grid memory and leaves stamping cost unchanged (each source stamps once into its group).
* Detection stamps only for detectors (about 25 % of movers), so the `det` grid adds about 25 % to the stamping cost.

### 9.2 Mitigations (all count-bounded and deterministic)

1. **Re-stamp budget.** `restamp_budget` crossings are processed per vision update: 128 (Normal) or 64 (Low), a match-level setting (`MatchRules.vision_budget`, identical on all clients). Crossings beyond the budget wait in an eid-ordered ring queue; a queued unit that crosses again simply updates its target cell (no duplicate entries), so the backlog never exceeds the number of movers. Lag is `ceil(crossing demand / budget)` updates: 135 crossings against 128 lags one update; a pathological 480-mover march against 64 lags about 4 updates (0.4 s, about 1 cell for a moving unit). Vision therefore trails slightly in extreme marches but never diverges between clients. Bounded cost per tick at Normal: 64 crossings x 290 statements = 18.6k = 2.8 ms laptop; at Low: 1.4 ms.
2. **Moved-list request.** Sim-core publishes `world.moved_prev2` (entities whose position changed during the last two ticks, ascending). Vision scans only those instead of every mobile entity.
3. **Stride.** `SimVisionSystem.stride` is 2 (`MatchRules.vision_stride`; 3 for Low). It reduces the fixed scan cost, not the crossing cost.
4. **Lazy stat refresh** with per-key dirty masks, and **watch-list minimalism**: entities enter `watch_list` only when a def or research effect needs `STILL`, `CELL` or `COMBAT`; structures never do.
5. **No allocation in hot loops**: scratch `PackedInt32Array`s (`changed_cells`, `tmp_ids`, `pulse_members`) are created once and reset with `resize(0)`.
6. **Bounded structures**: sight radius at most 32 cells, disc tables built once per world, 64 temp sources, 96 zones.
7. **Possible later optimisation (not planned):** coalescing co-located sources of one group by `(cell, radius)` multiplicity; reduces stamping in tight blobs by an estimated 30 to 50 %.

### 9.3 Calibration gate

The statement cost above is an estimate. The first acceptance test of task AB-05 is a headless micro-benchmark (`game/tests/bench_vision.gd`, run through `tools/gd run`) that reports nanoseconds per counted cell write and per timer dispatch on the developer machine. Decision rule: if a `move_disc` step of R = 8 costs more than 12 microseconds, the default preset becomes Low (`vision_budget = 64`, `vision_stride = 3`); results go into `docs/STATUS.md` by the QA architect. The determinism test asserts *counters* (`stat_cells_written`, `stat_restamps`), never wall time, so the budget is enforced by tests without wall-clock dependence.
