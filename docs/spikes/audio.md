## Verdict

GO. Zero-external-asset AAA-style audio is feasible, cheap and reproducible. From code alone: 38 SFX recipes (+18 mono downmixes), 2 loopable 4-stem tracks (combat 32 bars @140 BPM = 54.9 s, calm 16 bars @84 BPM = 45.7 s), 52 announcer lines = 116 Vorbis OGGs, 13 MB, built in about 20 s (SFX) + 4 s/track (music) + 2 s/line (Kokoro voice), bit-reproducible (two full rebuilds: 38/38 WAV sha256 and 56/56 SFX OGG byte-identical). Godot 4.7.2 imports everything as AudioStreamOggVorbis; loops are sample-exact through the engine decoder AND mixer. Announcer is de-risked with Kokoro-82M (Apache-2.0) at build time; macOS `say` must not ship. Three binding rules only measurement revealed: (1) positional SFX must be MONO files (stereo streams are not spatialised), (2) a current Camera3D must exist in the listener viewport (AudioListener3D alone was silent), (3) every volume change must be ramped at >=60 Hz (bus / AudioStreamSynchronized steps click ~21-23x). Caveat: nothing could be listened to; quality was judged with LUFS/true-peak, envelope, spectral, stereo, loop-seam metrics and spectrogram PNGs (all inspected); human ear review is still required. Linux/Windows audio drivers were not measured.

## Key findings

1. TOOLCHAIN (py/): dsp.py is numpy-only (rules of tools/py): frequency-domain periodic noise colours, PolyBLEP osc, FM, wavetable, modal, Karplus-Strong, multi-segment envelopes, RBJ biquads run as FFT convolution of the closed-form impulse response (max error 1e-9 vs scipy.lfilter, no per-sample loops), sweep_filter (cross-faded filter bank = stable time-varying filters), saturation/fold/bitcrush, look-ahead limiter, echo, synthetic-IR reverb (circular mode wraps tails), M/S widen, decorrelate, LR4 bass_mono, bass_exciter, true-peak, rng_for(name) per-asset seeds (adding a sound never perturbs others). sfx.py = 38 recipes; music.py = Flavour hooks (bpm, root, 10 scales, kit electro/taiko/brush, bass/pad/lead timbre, swing, seed) + 8 faction presets; voice.py = Kokoro -> ffmpeg 'computer'/'radio' chains; oggtools.py = libvorbis encode + Ogg serial/CRC rewrite.

2. ENCODER PITFALL: Homebrew ffmpeg 9.0.1 has NO libvorbis. Its native vorbis encoder is stereo-only ('only supports 2 channels'), ignores -b:a (identical size at 96/128/192k), pads +16..32 samples (breaks loop lengths) and is much worse (rifle SNR 10.6 dB vs 26.7 dB libvorbis q~7). Solution: libvorbis through the `soundfile` wheel (BSD-3, bundles libsndfile+libvorbis): true mono, exact length (len delta 0), quality control (compression_level 0.3~q7, 0.4~q6, 0.5~q5). libsndfile picks a random Ogg serial, so oggtools.fix_serial rewrites serial + page CRCs => byte-reproducible. Also: system python3 numpy import was broken (namespace stub without __version__), Pillow/scipy absent => tools must bootstrap a venv (.cache/venv used; scipy only for verification).

3. SFX ITERATION v1->v2: rifle was boomy (centroid 595 Hz, t40 531 ms) -> crack+supersonic snap layering: 1018 Hz, 293 ms. Loudness spread was 22 LU (countdown_final -5.4 LUFS) -> K-weighted gated LUFS targets (own numpy meter agrees with ffmpeg ebur128 within 0.2 LU). Coast-wave foam had a hard step (rectangular block in spectrogram) -> smooth build-up. Rail echoes low-passed, siren sub cut.

4. SFX ITERATION v2->v3: tank/howitzer/explosions had 92-98 % of power below 200 Hz (would vanish on laptop speakers) -> psychoacoustic bass_exciter: 200 Hz-2 kHz power share tank 2.2->7.0 %, howitzer 1.1->4.8 %, explosion_small 2.5->7.3 %, power_down 10.6->14.1 %. Decorrelated LF made booms mono-incompatible -> LR4 crossover, everything <140 Hz centred (LF L/R corr >= 0.93). True peaks: rifle_shot_3 was +0.8 dBTP -> true-peak normalisation, all SFX now <= -1.4 dBTP (target -1.5). v4: mono downmix variants for positional use (18 files).

5. MUSIC: all stems rendered CIRCULARLY (wrap-around note placement, circular FFT reverb/filters/echo) so the loop point is seamless by construction; kick sidechain pump on pads/bass; per-style stem LUFS balance then ONE shared master gain, so the 4 stems sum to the reference mix. v1->v2 balance fixed (drums -24.8 / pads -18.4 LUFS -> -18.1 / -23.1 / bass -20.1 / lead -21.1). Mix: combat -14.4 LUFS, calm -16.1 LUFS, both -2.0 dBTP. Tempo estimate 138 vs 140 and 85.3 vs 84 BPM; 90 % / 94 % of pitched energy inside the target scale. Faction demo (8 presets x 8 bars): 7/8 tempo within 1.6 % (napc detected at half-time, estimator ambiguity), 80-90 % in-scale; spectrograms show distinct rhythm/timbre per faction. Integer-sample-friendly BPMs (140 = 18900 samples/beat, 84 = 31500) give exact bar grids; other BPMs still loop exactly because loop length is rounded once.

6. LOOP VERIFICATION (three levels): (a) source WAV seam_score (|x[0]-x[-1]| / typical step; ~1 for any adjacent pair, >4 = click): 9 SFX loops 0.07-2.05, 8 music stems 0.00-2.88, decoded OGG 0.04-3.06, OGG length delta 0 samples. (b) inside Godot's decoder (AudioStreamPlayback.mix_audio across the loop point): jump / p99-step <= 0.99 for all 8 stems. (c) through the REAL mixer (AudioEffectCapture on Master, AudioStreamSynchronized, intensity 1, play(len-1 s)): engine gain -0.002 dB vs offline stem sum, 43.6 dB match SNR (16-bit capture limit), seam step 0.52x the p99 step => no click.

7. GODOT IMPORT (t_import.gd, PASS): 116/116 OGG load as AudioStreamOggVorbis; load() of all takes 69-256 ms; cold `--headless --import` ~13 s. OGG importer params: loop, loop_offset, bpm, beat_count, bar_beats; editing the .ogg.import sidecar (loop=true,bpm=140,beat_count=128) + reimport yields a pre-configured stream while untouched stems keep defaults (verified) - so the asset generator can author loop/BPM metadata. 8. ENGINE FACT - listener: in headless SceneTree tests an AudioStreamPlayer3D was SILENT with an AudioListener3D alone in the root viewport; with a current Camera3D present, the AudioListener3D overrides the camera transform (listener at 110 m gave exactly -20.8 dB); an audio-only SubViewport (audio_listener_enable_3d) + Camera3D also tracks correctly. Listener-only inside a SubViewport gave an inconsistent -29.9 dB (not investigated). Rule: always keep a current Camera3D in the viewport that holds the players (the RTS camera does); put the AudioListener3D on the ground focus point so attenuation is relative to the battlefield, not camera altitude. Windowed listener-only behaviour was not separately tested.

9. ENGINE FACT - stereo in 3D: AudioStreamPlayer3D does NOT downmix. An L-only stereo file stays in the left ear wherever the source is (source hard right: L -17.9, R -46.1 dBFS). Therefore positional events must use mono files (build emits <name>.mono.ogg for stereo sources; 3D events reference them), and stereo is reserved for 2D/global/UI/beds/music. Panning is a simple pan: mono source hard-left/right at panning_strength 1.0 gives L/R 6 dB apart (0.5 -> 2.5 dB, 0 -> equal); front and behind are identical (no front/back cue).

10. ENGINE FACT - attenuation (unit_size=U, measured with capture, noise source): inverse = -20log10(d/U); inverse_square = -40log10(d/U); logarithmic = -20*ln(d/U); all within ~0.8 dB of theory; gain clamped at +3 dB (max_db) inside U; disabled = flat. max_distance is NOT a cutoff: it multiplies by a linear fade (1-d/max): -6 dB at half of max_distance, -20 dB at 90 %, silent at max. Set max_distance 2-3x the audible range; the pool's attenuation_db() models model + window. attenuation_filter_cutoff_hz (default 5 kHz) is distance-driven: at 40 m 4 kHz is -15 dB and 8 kHz -30 dB, none at 5 m, ~30 % extra CPU; use 9-12 kHz for weapons, 20500 disables it.

11. ENGINE FACT - ducking: AudioEffectCompressor.sidechain = &"Voice" on the Music bus ducks music with zero per-frame code. Measured Music drop with a REAL announcer line: (threshold -24 dB, 4:1) = -17.0 dB (too deep); (-18 dB, 3:1) = -8.8 dB (chosen default); (-14 dB, 2.5:1) = -2.6 dB. Noise-based tests understate/overstate depth, so tune with real lines. Master gets AudioEffectHardLimiter (ceiling -1 dB).

12.
