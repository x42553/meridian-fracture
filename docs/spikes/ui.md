## Verdict

GO. Stock Godot 4.7.2 Control + Theme + CanvasItem is enough for a C&C-class HUD, cinematic menus and a LAN lobby with zero external art (vector chamfered StyleBoxes, procedural glyphs/emblems, 3 vendored OFL fonts, 3D-model portraits baked at runtime). The whole HUD costs about 1-2 ms CPU per frame at 1080p on the M5 Max and works unchanged on Forward+, Mobile and gl_compatibility. Caveats: several engine pitfalls (below) cost real time and must be baked into the architecture; a scripted StyleBox is expensive if redrawn every frame; GPU time could not be measured on Metal.

3. THEME DESIGN: UiStyleBox extends StyleBox overriding _draw(to_canvas_item: RID, rect: Rect2) with RenderingServer.canvas_item_add_polygon/polyline (cut corners, vertical gradient, inner glow, accent brackets). It plugs into Theme like a built-in stylebox (PanelContainer.panel, Button.normal/hover/pressed/disabled, ProgressBar.fill, PopupMenu.panel/hover, TooltipPanel) so every Control - including OptionButton popups, which are embedded windows and appear in viewport screenshots - gets the look; vector so crisp at any UI scale. Faction tint = UiTheme.build(UiSkin) again (0.27 ms warm, ~5-9 ms first call). Skin = 3 colours (accent, accent2, dark tint) derived from bible visual_direction; verified on NAPC (orange) and HAN (jade). Type variations: HeaderLabel DimLabel NumLabel TitleLabel CreditsLabel InsetPanel SidebarPanel RibbonPanel PrimaryButton HeroButton CommandButton GhostButton. Custom-draw widgets (UiIconButton, cards, minimap) extend Control and fetch styles with get_theme_stylebox(state, &"Button"); rich tooltips via Control._make_custom_tooltip returning a frameless body (Godot wraps it in the themed TooltipPanel).

4. PITFALL 1 (biggest): Window.theme is NOT inherited by Controls whose parent is a CanvasLayer (labels stayed default font, PanelContainers unstyled). Assign `theme` on the first Control below the CanvasLayer (screen root); tooltips/popups of descendants then inherit it. PITFALL 2: set_anchors_preset(PRESET_FULL_RECT) on a code-built Control under a CanvasLayer left size (0,0) and collapsed everything anchored below it; use set_anchors_and_offsets_preset. PITFALL 3: TextServer.name_to_tag() is not static; FontVariation.variation_opentype needs {TextServerManager.get_primary_interface().name_to_tag("wght"): 700}. PITFALL 4: draw_multiline_colors wants ONE colour per segment, not per point; draw_polygon/canvas_item_add_polygon have no antialiased param (use msaa_2d + an AA border polyline; msaa_2d is unsupported on gl_compatibility and warns). PITFALL 5: OptionButton.fit_to_longest_item defaults true and wrecks column layouts; bitmap theme icons (checkbox/arrow) do not scale crisply. PITFALL 6: the --headless root Window is 64x64; run layout/input tests inside a SubViewport of the desired size (SubViewport has no get_viewport_rect(); use get_visible_rect()). PITFALL 7: the doc XMLs in tools/godot_docs are signature-only (descriptions stripped), so behaviour must be verified empirically. PITFALL 8: Performance.RENDER_TEXTURE_MEM_USED underflows on Metal (1.7e13 MB); viewport_get_measured_render_time_gpu returns 0.0 on Metal; frames stay pinned to the 120 Hz display even with --disable-vsync.

5. SCALING / HIDPI RULE (verified at 0.75, 1.0, 1.5): project display/window/stretch/mode=disabled and Window.content_scale_factor = clamp(window_pixel_height/1080, 0.75, 2.0) * user_scale. content_scale_factor works with stretch disabled and text is re-rasterised crisp (screenshots at 1280x720@0.75 -> 1706x960 logical, 1920x1080@1.5 -> 1280x720 logical). On this Retina Mac DisplayServer.screen_get_scale()=2.0 yet --resolution 1920x1080 produced a 1920x1080-PIXEL window (Window.size is in pixels), so the pixel-height rule needs no screen_scale math. Design canvas 1920x1080 logical, sidebar 348 px. Responsive breakpoints implemented in UiHud (logical height < 800): minimap = clamp((h-420)*0.55, 180, 300), hide queue strip + footer; selection panel width = clamp(playfield-40, 600, 900). Min physical text size guidance: 12 px only for CAPS/tertiary, 14-16 body.

6. FONTS (OFL, downloaded from raw.githubusercontent.com/google/fonts, vendored in prototypes/ui/fonts with OFL texts): BODY Rajdhani SemiBold, BODY_BOLD Rajdhani Bold, HEAD Orbitron variable (wght axis works via FontVariation; advances barely change with weight: 440->442 px at 22 px for 400->900, so weight is layout-safe; spacing_glyph gives letter-spacing), NUM Share Tech Mono (tabular digits). Verdict at 12-18 px on #0b1016: Rajdhani is the densest and most legible (fits 'Liberty Arsenal..' in 90 px at 14 px bold); Medium is too thin below 16; Orbitron only for CAPS/numerals (lowercase poor under 14 px); Share Tech Mono thin at 12, prefer >=13. Rejected: Exo 2 (generic/wide), Chakra Petch (nice for menus but redundant), Saira Condensed (glyphs tiny at 12-14), Rajdhani Medium. Rajdhani is ~390 KB/weight (Indic glyphs): subset to Latin in tools/py if PCK size matters. Project font settings used: grayscale AA, light hinting, subpixel auto. Roles live in UiFonts so a swap is a one-line change.

7. BUILD CARD + SWEEP DESIGN: UiBuildCard is a single custom-drawn Control fed by a UiBuildItem view-model (cards never read the sim); states AVAILABLE/BUILDING/QUEUED/READY/ON_HOLD/LOCKED/UNAFFORDABLE/COOLDOWN; static text/frames redraw only on state change or once per displayed second; per-frame progress goes to a child UiCooldownSweep. Three interchangeable back-ends were benchmarked: canvas_item SHADER with a progress uniform (0.11 ms for 100 sweeps changing every frame), TextureProgressBar radial (1.54 ms), GDScript fan polygon (1.55 ms, twice the draw calls) -> use the shader. The time label is a Label child ABOVE the sweep so the sweep edge line does not strike through it. Progress semantics: clockwise from 12 o'clock, shaded = not yet finished. Icons are drawn with draw_texture_rect inside a fitted rect; baked at 2x (188x124 for a 94x62 slot) so UI scale up to 2 stays sharp.

8. ICON BAKER (UiIconBaker): create N SubViewports in ONE frame (size, transparent_bg=true, own_world_3d=true, msaa_3d 4x, render_target_update_mode=UPDATE_ONCE, positional_shadow_atlas_size 0), each with a model, an ORTHOGONAL Camera3D fitted from the 8 AABB corners projected on the camera right/up axes (keep_aspect KEEP_HEIGHT, +10% margin), Environment BG_CLEAR_COLOR with ambient colour, 3 DirectionalLights (key, cool fill, faction-coloured rim) and a radial-gradient quad as contact shadow; then a single `await RenderingServer.frame_post_draw`, get_texture().get_image() + Image.fix_alpha_edges() -> ImageTexture, free the viewports; cache key kind|WxH|team colour. transparent_bg also works on Mobile and gl_compatibility. The model source is an injected Callable(kind, team)->Node3D so the game plugs in ViewModelBuilder. The same baker feeds cards, selection tiles, queue strip, skirmish roster strip.

9. MINIMAP (UiMinimap): custom _draw of terrain ImageTexture + fog ImageTexture + vector dots (draw_rect per entity) + camera-frustum polygon (screen corners ray-cast to y=0 via project_ray_origin/normal + Plane.intersects_ray) + expanding-ring pings + radar sweep wedge + grid ticks, redrawn at 30 Hz; data in through set_dots(norm positions, colours, sizes) / camera_quad, signals out camera_requested(norm) and order_requested(norm). Input: LMB press then drag keeps emitting even outside the rect (implicit mouse grab for the Control that got the press), RMB = move order; accept_event() in _gui_input. Cost: 0.23 ms per redraw for 439 dots. UiWorldOverlay draws selection brackets (one draw_multiline_colors for all) + hp bars: 0.67 ms for 377 visible entities per frame (cull off-screen; only selected/damaged get bars).

10. INPUT - VERIFIED BEHAVIOUR (src/screens/ui_input_lab.gd, events via Viewport.push_input): (A) a full-rect HUD root with mouse_filter STOP (Control default) eats every world click, `_unhandled_input` never runs; PASS lets the click through after the root's gui_input; IGNORE goes straight to `_unhandled_input` -> the root must be IGNORE. (B/C/D) STOP panels consume clicks; a Label (IGNORE) inside falls through to the panel; Button pressed fires on release. (E) a panel set to PASS LEAKS clicks to the world. (G) press on Button + release in world: Button still gets the up event (implicit grab), world gets nothing. (F) naive `_unhandled_input`-only drag: press in world, release over sidebar still delivers the release, but motion over the STOP sidebar is swallowed so the rectangle freezes. Pattern in UiInputController: start gestures in `_unhandled_input` (never starts on HUD), continue in `_input` (runs before GUI) and consume motion/release, poll Input.is_mouse_button_pressed in `_process`, cancel on NOTIFICATION_WM_WINDOW_FOCUS_OUT / APPLICATION_FOCUS_OUT (verified). (L/L2) wheel over a STOP sidebar leaks to camera zoom because mouse_force_pass_scroll_events defaults true; setting it false on HUD panels stops it (verified). (K) RMB over sidebar is consumed - no world order. (N/N2/O/P/R) with a focused Button (FOCUS_ALL): arrow key is consumed when a focus neighbour exists, SPACE down+up fires the Build button; with FOCUS_NONE both reach `_unhandled_input`; erasing ui_focus_next/ui_focus_prev frees Tab. => every HUD control focus_mode=NONE; gate camera keys when gui_get_focus_owner() is a LineEdit (chat). (actions) loose is_action on ctrl+1 matches BOTH group_select_1 and group_assign_1, exact_match=true fixes it; a hand-made InputEventKey needs physical_keycode to match actions bound with physical_keycode (letters use physical keys so WASD-style grids survive AZERTY). (hover) Viewport.gui_get_hovered_control() is non-null over the sidebar and null over the world when the root is IGNORE - a usable 'pointer over UI' probe. Edge scroll = pure function UiInputController.edge_direction(pointer, rect) returning zero outside the window; gate on Window.has_focus(), optional Input.mouse_mode=CONFINED. Picking without physics: UiPicking.ray_pick (ray vs sphere) and box_select (unproject_position + is_position_behind). Integration proof: hud_dragselect_midflight/released.png inject a real drag through Input.parse_input_event and the selection panel + brackets update.

11. MENUS: main menu = live 3D hero scene (procedural dusk desert, heavy tank, drifting CPUParticles3D dust, volumetric fog on Forward+ only, camera slowly orbiting in _process) + UiVignette (one canvas shader: vignette, letterbox bars, left text scrim, scanlines) + logo (Orbitron wght 900/500 with spacing_glyph) + HeroButton stack + featured-faction card + status chips. Camera3D.h_offset/v_offset shifts the subject out from under the menu column without moving the camera. Skirmish: 8 slot rows of real OptionButtons (type, faction with 8 bible factions + Random, subfaction Vanilla + 3, team) with emblem + colour swatch + status; hovering a row drives the briefing (name, motto, identity, subfaction modifiers text, roster delta: replacements/removed from the bible) and a wrapped UiRosterStrip of baked unit portraits with UNIQUE badges; map preview (terrain image without building 3D nodes) with numbered start markers; rules (credits, speed slider, unit cap, checkboxes). LAN lobby: UiListRow custom-drawn rows (one canvas item per row), compatible/old-build/data-hash-mismatch states, full-game dimming, detail card with 8 player slots, chat, direct-connect IP:port (default 27615).

12. RENDERERS: Forward+ and Mobile render the UI identically (Mobile has no SSAO/volumetric fog; guarded by RenderingServer.get_current_rendering_method()). gl_compatibility: all chrome, custom StyleBoxes, canvas shaders, fonts, and transparent-bg SubViewport icon bakes work (skirmish_gl_compatibility.png shows baked roster icons); differences are brighter 3D grading, no volumetric fog/SSAO, and 'WARNING: 2D MSAA is not yet supported for GLES3' whenever msaa_2d is set (guard it). On macOS GL-on-Metal gl_compat is CPU/draw-call bound, so the 683 HUD draw calls matter more there. Cold shader/pipeline cache: the first 3D bake stalls 2.6-2.8 s on Metal (Forward+ and Mobile), 1.5 s on GL, 70-250 ms warm -> pre-warm behind the loading screen.

13. OTHER API FACTS: Control.mouse_filter default STOP for Panel/PanelContainer/Button, IGNORE for Label; PopupMenu/OptionButton popups honour the theme's PopupMenu styles and are captured by root-viewport screenshots (embedded subwindows); Viewport has oversampling/oversampling_override, disable_3d, msaa_2d, scaling_3d_scale (3D can be scaled independently of the UI); Node3D.look_at_from_position and Camera3D.h_offset available; FastNoiseLite/ArrayMesh.add_surface_from_arrays are fast enough for a 120x120 procedural terrain in ~50-100 ms; Image.fix_alpha_edges avoids dark fringes on baked transparent icons; --headless still runs full GUI/input logic (used for the lab); Movie Maker (--write-movie) exists for later animation captures. Measurements ran while other agents used the same machine: expect +-2-5x noise on GPU-bound or readback-bound numbers (icon readback ranged 60-400 ms per 34-icon batch across runs).

14. REQUESTS / NEXT STEPS FOR ARCHITECTS: (1) ViewModelBuilder.build(def_index or kind, team_color) -> Node3D with origin on the ground plane and MeshInstance3D-only bounds so UiIconBaker.model_builder can call it; placeholder primitives cost ~1000 draw calls for 39 entities, so the real models need MultiMesh/merged meshes. (2) UI module owns UiHotkeys.DEFAULTS (rebindable, persist to user://settings.cfg) and must keep HUD focus_mode NONE. (3) Project settings: display/window/stretch/mode=disabled, msaa_2d=4x only where supported. (4) Vendor the 3 fonts + OFL texts under game/assets/fonts. (5) Pre-warm pipelines + bake the roster icons (~25 icons, ~65 ms warm; all 185 defs ~0.5 s and ~17 MB at 188x124) in the loading screen; optionally cache PNGs in user://cache keyed by data hash. (6) Production UiStyleBox should be baked to 9-slice StyleBoxTexture (300x cheaper per redraw) or cache its polygons; never queue_redraw styled panels every frame (keep animation in child controls/shaders as UiBuildCard does). (7) With more time: panel noise/scanline texture, backdrop-blur glass for the sidebar (screen texture shader), tweened panel/hover transitions, procedural context cursors, MSDF titles, PBR/AO-baked icon models with a team-colour mask, unit-testing widgets headless via the lab pattern, gamepad/keyboard navigation for menus.


## Performance

Machine: Apple M5 Max (40-core GPU), Metal 4, Retina (screen_scale 2.0), macOS arm64, Godot 4.7.2, 1920x1080 px window, 120 Hz display (frames stay pinned at 8.33 ms even with --disable-vsync; GPU timers read 0.00 on Metal so only CPU 'work' = scripts + deferred _draw callbacks per frame is reported). Measurements were taken while other agents used the machine.
Forward+ (Mobile in brackets): 3D placeholder battlefield only 0.07 ms work / 993 draw calls; HUD idle 1.17 ms (0.51) / 683 draw calls; HUD animated 1.27 (0.56); HUD at UI scale 1.5 0.77 / 633 calls; HUD + 400 moving entities 2.22 ms (1.25) incl. overlay draw 0.67 ms for 377 visible and minimap draw 0.23 ms at 30 Hz; MSAA 2D off/2x/4x/8x no measurable CPU difference.
Sweeps x100 changing every frame: shader 0.11 ms, TextureProgressBar 1.54 ms, GDScript polygon 1.55 ms (201 draw calls). On gl_compatibility (real-time bound): 3.5 ms vs 7.4 ms vs 6.3 ms frame.
StyleBox redraw x500 every frame: UiStyleBox (GDScript _draw) 45.8 ms (91 us each, 4401 draw calls), StyleBoxFlat 9.7 ms (401), StyleBoxTexture 0.15 ms (2). Text: 300 Labels changing text per frame 2.0 ms; 300 draw_string in one Control 1.17 ms. UiTheme.build 0.27 ms warm (5-9 ms first call). UiPicking.box_select over 439 entities 92 us, ray_pick 127 us (GL compat 130/155 us).
Icon bake (34 icons 188x124, one batch): build 14 ms + GPU wait 13.5 ms + readback/upload 60 ms = 87 ms (2.6 ms/icon); 96x64: 58 ms (1.7 ms/icon); one icon per awaited call 9 ms each; Mobile 2.35 ms/icon; gl_compat 4.9 ms/icon; readback ranged 60-400 ms per batch under machine load. Cold pipeline cache: first bake GPU wait 2.6-2.8 s (Forward+/Mobile Metal), 1.5 s GL, warm 73 ms. Memory: 34 icons at 188x124 RGBA8 ~3.2 MB; 185 defs ~17 MB.
gl_compatibility HUD-only idle: 6.3 ms frame, 3.5 ms render CPU (Metal: 0.2-0.5 ms); 3D+HUD 10.0 ms frame; empty viewport 1.5 ms.
